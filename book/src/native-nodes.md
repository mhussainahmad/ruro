# Nodes in C and C++

Nodes written in C or C++ are compiled into a shared library, a **plugin**, that the host
loads into its own process. They run there next to Rust nodes, without a process boundary
or serialization: typed ports, parameters with ranges and live changes, metrics, the
emergency stop, recording and replay work as for Rust nodes. Code that MATLAB Coder or
Simulink generates is C, and fits the same way (see below).

> **Status:** implemented and tested in CI, on x86-64 and, under emulation, on 64-bit ARM:
> a C plugin that passes every standard message type through and back field by field,
> parameters, timing, the e-stop and errors; a C++ plugin (parameters, images, exceptions
> from constructors and steps); plugins refused for another ABI version, another struct
> layout or a missing entry point; the examples in `examples/native`; and a graph running a
> C++ node through a real daemon. Not tried: code generated by MATLAB Coder or Simulink.

## A node in C++

```cpp
// examples/native/threshold.cpp (abridged)
#include <ruro/ruro.hpp>

class Threshold : public ruro::Node {
public:
    static ruro::Spec spec() {
        return ruro::Spec("example/cpp-threshold")
            .doc("Black-and-white images, in C++.")
            .input<ruro::Image>("image")
            .output<ruro::Image>("mask")
            .param("level", int64_t{128}, 0.0, 255.0, "brightness above which a pixel is white");
    }

    explicit Threshold(ruro::Builder &b)
        : in_(b.input<ruro::Image>("image")),
          out_(b.output<ruro::Image>("mask")),
          level_(b.param<int>("level")) {}

    void step(ruro::Ctx &) override {
        auto img = in_.latest();  // the newest image, if one arrived
        if (!img) return;
        // ... compute mask_ from img->data.ptr, img->width, img->height ...
        out_.send(ruro::Image{img->width, img->height, RURO_MONO8, ruro::view(mask_)});
    }

    bool set_param(const std::string &name, const ruro::Value &v) override {
        if (name != "level") return false;  // refuse changes to anything else
        level_ = static_cast<int>(v.i);
        return true;
    }

private:
    ruro::Input<ruro::Image> in_;
    ruro::Output<ruro::Image> out_;
    std::vector<uint8_t> mask_;
    int level_;
};

RURO_PLUGIN(Threshold)  // one or more node classes
```

`ruro.hpp` needs C++17. A node class has a static `spec()` (kind, documentation, default
rate, ports, parameters), a constructor taking a `ruro::Builder` (ports and parameter
values), and overrides `step`, and optionally `start`, `stop`, `on_estop` and `set_param`.
`Input<T>::recv()` takes the oldest queued message and `latest()` the newest, dropping the
rest; both return a `std::optional` whose value has the message's fields plus `seq` and
`stamp_ns`. `Output<T>::send()` sends. An exception from the constructor makes the node fail
to start; one from a step is counted and logged, and the node keeps running.

## A node in C

```c
// examples/native/lowpass.c (abridged)
#include <ruro/ruro.h>

static const ruro_port_desc inputs[] = {{"input", "std/Scalar"}};
static const ruro_port_desc outputs[] = {{"output", "std/Scalar"}};
static const ruro_param_desc params[] = {
    {.name = "alpha", .default_value = {.kind = RURO_FLOAT, .f = 0.1},
     .has_min = true, .min = 0.0, .has_max = true, .max = 1.0, .doc = "weight of each new sample"},
};

static int step(void *self, ruro_ctx *ctx) {
    lowpass *n = self;
    ruro_scalar s;
    while (n->api->recv(n->in, &s, NULL) == 1) {
        n->state += n->alpha * (s.value - n->state);
        ruro_scalar out = {n->state};
        if (n->api->send(n->out, &out) != 0) return 1;
    }
    return 0;
}

static const ruro_node_type lowpass_type = {
    .kind = "example/c-lowpass",
    .inputs = inputs, .n_inputs = 1, .outputs = outputs, .n_outputs = 1,
    .params = params, .n_params = 1,
    .create = create, .step = step, .set_param = set_param, .destroy = destroy,
};

RURO_PLUGIN_INIT(api, reg) { return ruro_register(api, reg, &lowpass_type); }
```

`create` declares the instance's ports (`api->input`, `api->output`), reads its parameters
(`api->param`) and returns the instance. `step` (required), `start`, `stop`, `on_estop` and
`set_param` receive it; `destroy` frees it. A callback that fails calls
`api->set_error("why")` and returns nonzero (`create` returns `NULL`). `ruro.h` documents
every function.

## Building and loading

```sh
# One library with both examples:
cmake -S examples/native -B build && cmake --build build
# or: make -C examples/native
# or, for a single file:
c++ -std=c++17 -shared -fPIC -I sdk/include -o libmy_nodes.so my_nodes.cpp

RURO_PLUGINS=$PWD/build/libexample_nodes.so ruro daemon
```

`RURO_PLUGINS` lists plugin libraries, or directories whose `.so` files are plugins,
separated by `:`. Hosts load them when they start (the daemon's hosts inherit its
environment), so restart the daemon after rebuilding a plugin. The node types then appear in
`ruro nodes`, `ruro check` and the studio; a plugin that cannot be loaded is reported on the
host's standard error and skipped. The headers are in `sdk/include` in a checkout, and in
`/usr/include/ruro` with the Debian package.

Plugins are built for the machine that runs the host: for a 64-bit ARM robot, compile them
with `aarch64-linux-gnu-g++` (or on the robot).

## Messages

Every standard message type has a struct in `ruro.h`; in C++ they are also named
`ruro::Scalar`, `ruro::Image` and so on. Their fields are those of the Rust types
(`ruro schema <type>`); strings are `ruro_str` (`ptr`, `len`), arrays `ruro_f64s` and the
like (`ptr`, `len`), images `{width, height, encoding, data}`, point clouds
`{xyz, len}` (`3 * len` floats).

A received message points into the host's message: numeric arrays, image data and point
clouds are not copied. Strings are copied, and end with a NUL, so they can be passed to
`printf` and `strcmp`. The view stays valid until the next receive on the same input or the
end of the callback, whichever comes first. A sent message is copied by the host before
`send` returns, so its arrays can live on the stack or in a reused buffer.

Each instance is called from one thread at a time; send only from within its callbacks
(sending from a thread of the plugin's own, such as a driver callback, is not supported).

The host checks that a plugin was compiled against the same `ruro.h`: it refuses one built
for another `RURO_ABI_VERSION`, or whose structs have other sizes, and says which.

## Costs

Measured with the test harness on a development machine
(`cargo test -p ruro-nodes-native --release -- --ignored --nocapture`): a step of the C++
gain node with one scalar costs about 290 ns, against about 230 ns for the same node in Rust
(`std/gain`), the difference being the conversion of each message to and from its C struct.
Inverting a 640x480 RGB image in C++ takes about 0.3 ms per image, its copy on sending
included.

## Code generated by MATLAB Coder or Simulink

MATLAB Coder turns a MATLAB function into C functions, and Simulink's Embedded Coder turns a
model into `<model>_initialize`, `<model>_step` and `<model>_terminate` working on input and
output structs. Either becomes a node by calling the generated functions from a C (or C++)
node: initialize in `create`, copy the inputs into the generated input struct and call the
step function in `step`, and send the outputs. For example, for a generated
`double lowpass(double u, double alpha)`:

```c
#include "lowpass.h"  /* generated by MATLAB Coder */

static int step(void *self, ruro_ctx *ctx) {
    node *n = self;
    ruro_scalar s;
    while (n->api->recv(n->in, &s, NULL) == 1) {
        ruro_scalar out = {lowpass(s.value, n->alpha)};
        if (n->api->send(n->out, &out) != 0) return 1;
    }
    return 0;
}
```

Build the generated sources into the same shared library. This has not been tried with
actual generated code. For MATLAB code run by MATLAB itself, without code generation, see
[Nodes in other languages](other-languages.md).
